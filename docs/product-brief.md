# BuildMe 产品简报：我们在做什么、为什么做、接下来请你发挥

> 版本：v1.0（2026-10-07）
> 读者：GPT / Codex（产品共创 + 实现）
> 用途：先让你理解产品的灵魂，再请你**提出新功能**。本文不是实现规格，规格见文末列出的 PRD。

---

## 1. 一句话

**BuildMe 是一个能「被看穿」的 AI Agent。** 学生用它干活的同时，能看见 Agent 内部每一步在做什么，能亲手给它加能力，能让它和「完全体」同场比赛，再把发现分享到社区。

## 2. 为什么要做

这是老师布置的项目，目标只有一个：**最大程度激发同学们学习 Agent 知识的兴趣。**

想让他们学会的东西：

- Agent 和 harness 是什么，一个 Agent 一轮对话里到底发生了什么
- 提示词怎么拼出来的、工具调用、上下文窗口与压缩、Skill、子 Agent、工作流
- 哪些 harness 好（Claude Code、Codex、Cursor……），好在哪里
- 怎样把这些工具用得更好（vibe coding 的实践）

### 我们面对的真实处境

- 学生已经能直接用到很强的 Agent。**「从零手写一个 Agent」压力太大，没人愿意学**，我们已经否决了这条路。
- **不出题、不评分、不做固定任务**。一旦像作业，兴趣就没了。
- 学生没有群聊，彼此之间缺少交流渠道。
- 预算有限：凡是**服务器端要花模型钱的功能都不做**（例如社区里的 AI 摘要）。学生在 App 里用自己配置的模型 Key。

### 我们的核心判断

> 不让学生「造」Agent，而是让他们**看见** Agent、**打开** Agent 的能力、**比较** Agent，最后**分享**自己的发现。

兴趣来自四件事，产品每个功能都应该至少命中一件：

| 动力 | 含义 | 已有的对应功能 |
|---|---|---|
| **好奇（看见）** | 黑盒被打开的那一下「原来是这样」 | X 光模式 |
| **掌控（动手）** | 我改了一个开关，它就真的变了 | 能力开关（我的 Agent） |
| **反差（比较）** | 同一个问题，两个 Agent 做法完全不同 | 双引擎对比（**最关键**） |
| **被看见（分享）** | 我的发现、我的作品有人点赞 | 社区、作品墙、成就、一键分享 |

## 3. 产品现在长什么样

桌面 App（Electron，Mac + Windows），两个引擎：

- **Pi（你的 Agent / 轻量版）**：从最简单的 Agent 起步，学生用开关一个个打开能力（Skill、压缩、子 Agent、工作流……），逐步长成接近完全体。
- **DSH（完全体）**：DeepSeek Harness 原生 agent loop，能力全开。

已经规划（部分在实现中）的模块：

1. **X 光模式**：每轮对话的时间线、提示词组成、上下文占用、原始请求（已脱敏）；任何一步都能点「这是什么」，还有「结合这一步详细讲讲」。分「新手 / 进阶」两档。
2. **能力开关**：9 个能力，零代码打开，带依赖关系；积木堆叠可视化；完全体专属能力显示为锁定。
3. **双引擎对比**：同一个问题，Pi 和 DSH 并排跑，工作区隔离，实时显示子 Agent 泳道、调用次数、tokens、耗时，结束后给出差异总结。
4. **成就系统**：不判对错，从 trace 自动识别「第一次」（第一次看到压缩、第一次派出子 Agent……），30 个积木徽章。
5. **社区网站**（可嵌进 App）：GitHub 授权或邀请码注册，帖子带标题、Markdown 长文、楼层回复、表情回应、热门上首页、搜索、防广告；**作品墙**展示学生用各种 harness 做出的作品，可按「用什么做的」筛选；App 里可一键分享对比结果和成就。

视觉方向：冷灰中性底 + 陶土色品牌色（你的 Agent）+ 蓝色只给 X 光 + 石墨色代表完全体；等距积木作为贯穿全产品的图形语言。样图见 `docs/design/buildme-ui-mockup.html`。

## 4. 设计原则（新功能必须遵守）

1. **零门槛先爽，再深入。** 打开 App 3 分钟内要有一个「哇」的瞬间。深度内容放在第二层，想看的人自己点。
2. **不考试。** 不出题、不打分、不排名学生的「对错」。可以有成就、有点赞，但没有不及格。
3. **用真实数据说话。** 讲解尽量绑定学生自己刚刚跑出来的 trace，而不是课本式的抽象说明。
4. **每个发现都能分享。** 能截图、能一键发到社区的东西，传播力是普通功能的好几倍。
5. **省钱。** 服务器端不调用模型。App 端额外的模型调用必须是学生主动点击触发，并提前告诉他大概花多少 tokens。
6. **两个引擎都不能坏。** 不删 `@deepseek-ai/*` 依赖，不改 DSH 上游源码。
7. **好看。** 商业产品级的精致度，沿用样图的设计语言，不用 emoji 当图标。

## 5. 请你发挥：提出新功能

我们想在现有模块之外**再多做一些功能**，让学生更愿意打开、更愿意玩、更愿意分享。请你大胆想，但每个点子都要说清楚它命中了第 2 节的哪种动力。

### 5.1 可以往这些方向想（只是起点，不必局限）

- **第一次打开的 10 分钟**：怎样让一个从没听过 harness 的学生迅速上瘾？
- **对比模式的玩法**：除了 Pi vs DSH，还能比什么？（同一引擎不同能力组合、不同模型、不同提示词、学生的配置 vs 同学的配置……）怎样让对比结果更有戏剧性、更值得分享？
- **把真实 harness 带进来**：学生日常用 Claude Code / Codex / Cursor，BuildMe 能不能帮他们理解这些工具在做什么、用得更好？（例如对照讲解、导入它们的配置或日志做可视化、Skill / AGENTS.md 写法实验）
- **Skill 与提示词的动手实验**：学生写一个 Skill 或改一段系统提示词，立刻看到行为变化。
- **社交与同伴**：同学之间怎么互相激发？（分享配置、复现别人的对比、挑战帖、作品墙互动）注意不要变成排名压力。
- **老师视角**：老师能不能低成本地看到班级的学习热度？（注意隐私，默认不上传任何对话内容）
- **好玩的小东西**：彩蛋、周报、回放、动画、可以挂在朋友圈的卡片……

### 5.2 每个点子请按这个格式写

```markdown
### <功能名>

- 一句话：
- 命中的动力：好奇 / 掌控 / 反差 / 被看见（可多选）
- 学生会怎么用（一个具体场景，从打开 App 写起）：
- 能学到什么 Agent 知识：
- 依赖哪些现有模块（trace / X 光 / 能力开关 / 对比 / 成就 / 社区）：
- 成本：开发量（S / M / L）；是否额外消耗模型 tokens，大约多少
- 风险或可能让人反感的地方：
```

### 5.3 交付要求

1. 先读完：`README.md`、`docs/architecture.md`、`docs/prd-xray-capabilities-compare.md`、`docs/prd-community.md`，打开 `docs/design/buildme-ui-mockup.html` 看样图。
2. 把点子写进 **`docs/feature-ideas.md`**：至少 15 个，按「影响力 ÷ 开发量」从高到低排序，最前面附一张总览表。
3. 最后挑出你最推荐的 **前 5 个**，说明为什么是它们、建议放在哪个里程碑之后做。
4. **这一步只写文档，不写代码。** 负责人选定以后，再为选中的功能写 PRD 并实现。
5. 有拿不准的地方，写进同一文件末尾的「待决问题」，不要自己假设后直接动手。
